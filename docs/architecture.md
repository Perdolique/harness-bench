# Architecture

## Status

The five initial architecture decisions are accepted from the [2026-09-04 research snapshot](research-snapshot.md), issue 2 provider-free controls, and three successful native subscription samples. Harbor 0.22.0 and Codex 0.153.2 passed the synthetic spike on macOS Apple Silicon with Docker Desktop Linux/arm64 containers. The owner accepted qualified go on 2026-09-05, and issue 3 records the evidence boundaries. This remains feasibility evidence rather than production validation.

## Ownership

| Component | Owns | Must not become |
| --- | --- | --- |
| Harbor | Container lifecycle, native-agent adaptation, configured network enforcement, artifact transport, trajectories, separate-verifier orchestration, supported regrade transport | The authority for project schemas, validation, grading, or trust decisions |
| `benchctl` and project tooling | Config resolution, immutable harnesses, run manifests, trusted collector/verifier contracts, experiment plans, normalization, integrity gates, grading, statistics, reports | A second container orchestration framework |
| Task package | Prompt, fixed base, environment recipe, evidence-backed rubric, declared artifact interface | Agent-visible hidden grading material |
| Verifier | Fresh base reconstruction, safe patch application, deterministic checks and structured evidence | A reused agent workspace |

The package boundaries are `apps/benchctl` and `packages/{schemas,core,results,statistics,reporting}`. `packages/schemas` owns the frozen version-1 Valibot contracts for stack, harness, suite, experiment, task, run, and score documents. `packages/core` owns immutable harness tooling, issue 7's one-assignment resolution, Harbor invocation, evidence validation, immutable initial/completion records, the shared safe credential-pattern scanner, and issue 12 doctor definitions, input checks, deterministic Harbor controls, and sealed evidence. Doctor reuses the production task-package and evidence validators; its versioned definition/report documents do not change frozen schema v1. `packages/results` owns normalization, restricted records, metadata-only exports, disposition tombstones, and read-only verified sources for single-run and experiment analysis; it does not alter the frozen schemas package. `packages/statistics` owns issue 11's revisioned compatibility gates, paired estimators, reliability, distributions, and deterministic task-cluster bootstrap. `packages/reporting` owns pure single-run, experiment-comparison, and doctor terminal renderers. `benchctl` remains a thin argument, lease, and safe-output layer. Configurations live under `benchmark/{tasks,suites,stacks,experiments,harnesses}`; only sanitized synthetic repositories and deterministic provider-free fixtures belong in `fixtures/`.

## Versioned document boundary

Every serialized v1 document uses `snake_case`, carries `document_type` and `schema_version: 1`, rejects unknown fields, and keeps its schema version separate from content revisions. Task, suite, harness, collector, verifier, scoring, environment, runner, network-policy, and analysis identities change independently.

Version 1 freezes when issue 4 merges. Any later change to required fields, accepted or rejected document shapes, field meaning, or runtime relationship semantics requires a new schema version and retained v1 parser and inspection artifacts for existing records. Migration machinery is deferred until a second version exists; that deferral does not permit incompatible changes under `/v1/`.

Valibot schemas are the runtime authority. Checked-in JSON Schema Draft 2020-12 files are deterministic structural inspection artifacts. They do not encode every same-document or cross-document rule and must not replace runtime validation. Pure relationship checks validate references and harness-effect invariants from already loaded documents without reading files or starting Harbor.

## Execution and trust boundaries

```mermaid
flowchart LR
    S[Immutable stack, harness, task, budget] --> B[benchctl resolves and records plan]
    B --> H[Pinned Harbor]
    C[Dedicated external credentials] --> A[Fresh Codex agent environment]
    H --> A
    A --> K[Project collector via Harbor lifecycle]
    K --> P[Validated declared patch and metadata]
    P --> V[Fresh separate offline verifier]
    T[Immutable base and hidden checks] --> V
    A --> R[Restricted raw record]
    V --> R
    R --> N[Versioned normalization and reports]
```

The credential edge terminates at the native client. It is not permission for credentials to appear in workspace exports, logs, harnesses, or verifier inputs. Native CLI credentials are readable by agent-executed commands under the upstream adapter. This is an accepted residual threat under unrestricted internet, not a claimed secret broker. The host owns immutable task definitions and collector/verifier tooling.

Harbor supports explicit separate verifier environments, configured artifact transfer, and network baselines. Its defaults are shared verification and public networking. Planned tasks must explicitly select separate mode and a verifier `no-network` baseline. Agent setup and execution explicitly use Harbor `public` networking: ordinary Docker bridge access without an agent egress sidecar, hostname allowlist, or traffic observer. The separate verifier additionally sets Docker `network_mode: none`. Harbor may create its pinned no-network sidecar for that verifier; the verifier itself does not share its namespace. See [Harbor task configuration](https://github.com/harbor-framework/harbor/blob/4407eb5227a2ff4f0d3f16b2eb48849382fdf276/docs/content/docs/tasks/index.mdx).

The v1 host identity records the macOS version, Apple Silicon architecture, Docker Desktop and Engine versions, LinuxKit kernel, and container architecture. The network gate exercises public HTTPS from the actual agent container and checks loopback-only networking in the fresh verifier through Harbor's complete lifecycle. Passing on this target is not evidence for Intel Mac, WSL2, or an arbitrary remote Docker daemon.

## Collection proof and remaining scope

Do not ask Codex to export a patch and trust the result. Issue 2 demonstrated an independent snapshot/patch collector using Harbor's lifecycle: a trusted sidecar reads the stopped workspace with its own immutable baseline and collector, emitting a binary-capable patch plus metadata. Its deterministic controls and three native samples support the synthetic task only, not a general collector framework.

The upstream collection path runs main hooks before stopping the main service; sidecar collection follows a stop attempt, but stop failures are only warnings. Artifact failures are also best-effort. A usable record therefore requires evidence of successful quiescence, successful collection, complete inputs, and verified hashes. Missing or conflicted entries must fail closed. Agent-controlled `.git`, hooks, Git config, symlinks, and leftover processes cannot define the baseline or trusted diff. [Collection implementation](https://github.com/harbor-framework/harbor/blob/4407eb5227a2ff4f0d3f16b2eb48849382fdf276/src/harbor/trial/trial.py).

## Agent-visible Git snapshot

Future task environments contain a newly initialized local repository with exactly one base commit. That commit gives the native agent working `git status`, `git diff`, and related daily commands. Materialization does not copy the source object database, refs, remotes, hooks, credentials, or future history, and retains only objects reachable from the new commit. The task records source provenance outside the agent-visible repository. The trusted collector still computes changes from its own immutable baseline and ignores agent-controlled `.git` data.

This removes local Git history; it does not make publicly reachable history secret. Because the agent has unrestricted internet, a production task is eligible for hidden-material or future-history claims only when its grading material and later solution are unavailable from public repositories, mirrors, packages, caches, or other reachable sources. The public synthetic fixture may validate plumbing, but it cannot by itself prove online secrecy.

The completed issue 2 runs remain Git-free evidence. Issue 6 implements and tests the synthetic one-commit snapshot; issue 14 applies the same rule to imported real tasks and proves future-history removal.

Harbor implicitly transfers `/logs/artifacts` as well as configured inputs. The artifact contract must account for that directory, reject undeclared contents and paths that overlap verifier code or credentials, and prevent arbitrary material from entering trusted execution. Host-side artifact destinations do not remap the absolute replay paths. The verifier validates input before applying it.

## Results and failure handling

Write an immutable initial manifest before the agent starts. Append completion and derived-result records referencing it; do not mutate the initial record to add results. Keep raw Harbor files, native JSONL/session evidence, the adapter's merged `codex.txt`, logs, collected patches, hashes, verifier outputs, and provenance in a configurable ignored local run root. Each completed run is immutable and has its own ID.

For issue 7, `benchctl run` resolves exactly one preassigned experiment run and delegates task environment creation, agent adaptation, main-service shutdown, sidecar collection, and separate verification to pinned Harbor. Project code supplies the validated native Codex config, skills, MCP declarations, resource/concurrency controls, immutable records, and fail-closed evidence checks; it does not reproduce Docker lifecycle logic. The canonical runner-control digest excludes run-local paths and harness bytes, while the complete materialized Harbor config remains raw evidence. Issue 10 adds matrix generation, blocked scheduling, verified resume, and explicit whole-block replacement over this executor. Core owns separately versioned experiment-definition, plan, and progress contracts, resolution, leases, and sequential invocation. Results owns verified state assembly, normalization recovery, and sealed comparison-source rereads. `ExperimentComparisonSource` is a trusted in-memory read model created only by that Results reader; it is not serialized or accepted from an external caller, and its resolved absolute paths are not report content. Statistics performs defense-in-depth assignment and experiment-family checks before consuming the source without persistence, and reporting renders its returned analysis without recomputation. The CLI holds the experiment-family lease and composes those packages without moving statistical logic into the command layer. Frozen schemas v1 retain their existing meaning: the controller generates immutable valid in-progress assignment snapshots instead of inserting run IDs into planned v1 blocks or rewriting a run's original plan reference.

The matrix plan freezes every assignment and input digest. Local progress is a sequence of immutable hash-linked records; child plans freeze a parent-progress boundary and require an explicit parent supersession record. Carried runs are checked against their creating plan rather than relabelled with the child revision. A local per-user subscription lease is shared with standalone execution across run roots; experiment-family leases serialize controller changes within a run root. Stale leases require trusted local recovery. Harbor continues to own all environment and verifier lifecycle work.

Secret scanning happens inside the restricted raw root before host replay, grading, hashing, and read-only finalization. A suspected secret quarantines the record and blocks a valid grade, retention, or publication. Harbor `0.22.0` does not expose a host pause between sidecar collection and its built-in separate verifier, so the host scan cannot honestly be claimed to precede Harbor's verifier. The verifier must independently report credential absence, and the host rechecks the complete raw tree after Harbor exits. Scanning does not prove that all secrets are absent and does not prevent exfiltration while the public-network agent is running.

Normalization preserves authoritative facets, absent values, statuses, available usage, and upstream provenance. Harbor `reward.json` contains numeric metrics; non-numeric applicability, evidence, gates, and failure details need a separate structured verifier record. Unknown incompatible output formats fail explicitly. For subscription auth, an upstream API-price estimate is retained as upstream metadata only and never presented as actual money spent.

Issue 8 supports exactly Harbor `0.22.0` and, when present, `ATIF-v1.7`. It revalidates the sealed run directory, initial/completion/score relationships, raw manifest inventory, modes, sizes, executable bits, hashes, and a second post-parse source snapshot. Inventory hashing streams raw files rather than retaining the complete raw tree in memory. A valid grade additionally binds the completion collection claims to the retained trial log, exact artifact manifest, collector metadata, and collected patch, and binds the ATIF agent identity to the immutable initial record. A task outcome requires the native Codex rollout JSONL, ATIF trajectory, and Harbor's irreversibly merged `codex.txt`; execution failures preserve only references that actually exist and mark the rest unavailable. Agent and verifier durations come from complete Harbor timestamp pairs and round up to whole seconds. The completion total remains host-authoritative. Harbor trial token totals preserve known zero, and ATIF totals must agree when ATIF reports them. `cost_usd` is labelled as an upstream Harbor/Codex/LiteLLM API-price estimate; subscription money is always not applicable.

Derived records are new content-addressed files below `<runs-dir>/.results/<run-id>/{normalized,exports,regrades,restrictions}/<sha256>/`. Ordinary records contain `record.json`; a regrade leaf additionally contains its immutable target-input snapshot, raw Harbor evidence, and raw manifest. Records contain only run-relative raw references; resolved absolute paths are an API return value and never serialized. Experiment scoring-migration records are content-addressed separately at `<runs-dir>/.experiments/migrations/<sha256>/record.json`. Managed parents use mode `0700`, address directories `0500`, and record files `0400`. Normalization, export, regrade, and disposition use transient fail-closed per-run locks below `.results/.locks`; a batch regrade first holds the experiment-family lease, then takes all source-run result locks in deterministic order and invokes Harbor sequentially. A leftover lock requires trusted local recovery rather than an unsafe concurrent operation. A normalized or regraded record is created only after integrity and credential checks over source evidence and final serialized bytes pass. A credential finding or existing issue-7 quarantine blocks the derived commit. The safe scanner returns category and relative path, never matched bytes or their digest.

Sanitized exports are rebuilt field by field from an explicit metadata allowlist, reject path-bearing metadata, are scanned again as final serialized bytes, and are sealed separately while holding the same per-run result lock as restriction commits. They exclude prompt, source, patch, log and trajectory content, local and repository paths, tracebacks, and free verifier text. A clean export is only eligible for owner review; it is not publication authorization and no upload exists.

Private disposition requires one exact confirmed run ID. Before moving the canonical run, deletion installs a durable `<runs-dir>/.run-reservations/<run-id>` sentinel that both run planning and execution reject. It validates every managed derived record and content address, stages the source and derived state, removes only those paths, seals a truthful redacted tombstone after private deletion, and atomically installs it at the old run path. The canonical tombstone then prevents reuse and the separate reservation can be removed. A failure before deletion seals no false tombstone; a failure after deletion preserves the reservation and any sealed tombstone recovery state. Explicit incident retention leaves the restricted bytes in place, requires a new future expiry and credential rotation/revocation attestation, and writes a redacted disposition tombstone. The tool does not manage or claim deletion of external copies or perform credential rotation itself.

A scoring migration is an evaluation overlay, not a replacement run. Its target TaskDocument must preserve the task/source/environment/collector/prompt/artifact/scope/reachability/retention identity and may change only verifier, scoring, and rubric identities. Core validates the package and delegates transport to Harbor `trial regrade`; no agent environment or credential transport exists on this path. Results preserves the source agent identity, usage, and operational timings while attaching new quality, outcome, and separate verifier timing. Statistics rejects missing, cross-plan, extra, or mixed-evaluator overlays before pairing. Frozen schema-v1 score semantics remain unchanged; `regraded_run` is an independently versioned local contract whose strict score structure is bound to the selected scoring revision rather than the frozen v1 composite formula. Deleting a source run also validates and deletes its regrade leaves and every scoring-migration manifest that references it, recording all deleted content digests in the tombstone.

Task failure is a completed valid grade with failed checks. Agent, provider, runner, verifier, infrastructure failure, and cancellation are separate terminal classifications; timeouts retain their stage. A failed verifier gives no valid quality score. Regrades create new results from retained inputs without a provider call or rewriting the original run. See [methodology](methodology.md).

## Fallback sequence

Fallback depends on which capability is lost. If Harbor loses required native-agent adaptation while trustworthy collection and separate verification still work, stop dependent implementation and open a narrow issue and ADR for a supported `codex exec --json` Harbor adapter. If that is insufficient, host-managed Codex in an ephemeral Docker workspace may be evaluated only while the still-trusted Harbor collection and verifier boundary remains intact.

If Harbor loses trustworthy collection or separate verification, stop. A fallback that still relies on the lost property is invalid. Any Pier or alternative-boundary evaluation needs its own issue and ADR and must re-prove quiescence, independent capture, exact manifests and hashes, and fresh offline verification. Host execution increases host exposure. Accepted Git, auth-refresh, merged-stream, and public-network limitations do not trigger fallback by themselves. No competing kernel or custom sandbox/verifier platform is installed by default.
